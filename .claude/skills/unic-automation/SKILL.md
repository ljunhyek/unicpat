# 유니크 홈페이지 자동화 — 초안 작성 절차

서버(Vercel Cron, `lib/automation.js`)가 매일 감지·수집·알림·발송을 하고, 글 초안이 필요한 일은
관리자 화면 자동화 탭에 '할 일'로 남긴다. 이 스킬은 그중 **글을 써야 하는 일**을 처리한다.
API 비용을 쓰지 않기 위해(사용자 결정) 서버에서 AI를 부르지 않고 Claude Code가 직접 쓴다.

**저장 방식 (사용자 결정 2026-11-19, 비밀키 없음)**
- 칼럼 초안 → DB `columns`에 바로 저장(.env 기본 키로 가능) → 관리자 칼럼 탭에 '승인 대기'
- 뉴스레터·게시글 초안 → 프로젝트 폴더 `초안/`에 파일로 저장 → 관리자가 열어 보고 직접 올림
- `초안/`은 .gitignore 대상(공개 저장소에 올리지 않음)

## 0. 할 일 확인
`node scripts/auto.js tasks` — 요약이 빈 칼럼, 이번 달 뉴스레터 필요 여부, 게시글 초안 파일이 없는 최근 칼럼.
(자동화 탭의 할 일 목록과 같은 기준. 블로그 새 글이 아직 칼럼에 안 들어왔으면 관리자 칼럼 탭 [블로그에서 글 가져오기]나 자동화 탭 [지금 실행])

## 1. 칼럼 글 초안 — 블로그 원문 기반 긴 글 + 썸네일 + 영문 (2026-11-24 사용자 결정)
요약·핵심정리·CHECKPOINT는 더 쓰지 않는다(긴 글이 있으면 화면에도 안 나옴). FAQ와 '함께 읽으면 좋은 글'은 유지.

**내용 원칙 (사용자 요청)**
- 근거는 블로그 원문이다. 원문 내용·구성에 맞게 새 문장으로 다시 쓴다(그대로 옮기지 않음 — 유사문서 방지).
- 원문에 없는 내용을 더할 때는 신뢰할 수 있는 출처(법령: 국가법령정보센터, 판례: 대법원·특허법원, 특허청·특허심판원 공식 자료)로 확인된 것만, 본문에 출처(조문·판결번호)를 밝혀 넣는다. 확인 못 한 일반론·통계·지역 실태 주장은 넣지 않는다.
- 원문의 오류(예: 날짜 뒤바뀜)는 고치고 사용자에게 알린다. 추가한 부분은 끝날 때 사용자에게 목록으로 알린다.
- **원문과 다르게 쓴 곳은 모두 `초안/원문확인필요.html`에 항목(<div class="item">)으로 누적**하고(구분: 법령·사실 확인 / 오류 수정 / 표현·편집, 원문·홈페이지·이유·확인 결과 칸), Chrome으로 `초안/원문확인필요.pdf`를 다시 만든다. 사용자가 대표변리사에게 확인받는 문서(2026-11-24 요청). 법령·사실 확인 항목은 맨 위에.
  `"/c/Program Files/Google/Chrome/Application/chrome.exe" --headless=new --no-pdf-header-footer --virtual-time-budget=5000 --print-to-pdf=<pdf> file:///<html>`

**절차** (여러 개를 요청받으면 5개씩 묶어 진행 — 묶음마다 초안 확인 후 저장)
1. `node scripts/auto.js blog <글번호>`로 원문을 읽는다.
2. **새 제목**: 읽기 쉽게, 핵심 검색어를 앞쪽에, 가능하면 '인천' 지역 키워드.
3. **한국어 본문** `초안/칼럼_<글번호>_본문.html` — 루트 `구글블로그.html` 구성과 같게(인라인 스타일 없이 태그만, 스타일은 column-post.ejs `.post-article`):
   - 맨 위 `<figure class="post-thumb"><img src="{{thumbnail}}" alt="키워드 포함 설명" width="1200" height="630"></figure>`
   - `<p class="lead">` 도입(독자의 질문/고민) → 다룰 것 `<ul>` → `<h2>1. …</h2>`, `<h3>1.1. …</h3>`, `<table>`, `<blockquote>`(조문·판결), `<strong>` → `<h2>결론: …</h2>`
   - h1·연락처 상자·FAQ는 넣지 않는다(페이지가 붙임). FAQ는 `faq` 칸('Q.'/'A.' 3쌍) — 새 글만 쓰고 기존 FAQ는 유지
   - SEO: 네이버·구글 세부 검색어(예: '불사용취소심판 대응', '상표 사용증거')를 h2·본문에 자연스럽게, '인천 특허', '청라 변리사', '인천 상표' 같은 지역 키워드는 도입·마무리에(억지 반복 금지)
4. **영문 본문** `초안/칼럼_<글번호>_본문_en.html`: 한국어 본문을 같은 구조 그대로 영어로 번역(내용 추가·삭제 없음). 법령은 'Korean Trademark Act Article 119(1)(iii)', 판결은 'Supreme Court Decision 95Hu651, December 26, 1995' 식. 지역은 'Cheongna, Incheon'.
5. **썸네일** 1200×630, 한국어·영어 각 1장: `초안/thumb/spec_<글번호>.json`을 쓰고 `node scripts/thumb/make.js 초안/thumb/spec_<글번호>.json` → `<글번호>.jpg`, `<글번호>_en.jpg`
   spec: `{"no":"…","ko":{"tag","title"(줄바꿈 
, 강조 *단어*),"sub","steps":[2~3개 흐름 상자]},"en":{…}}` (영문 제목이 길면 `"size":54`). 여러 장은 PIL로 한 장에 모아 Read로 눈으로 확인
   (make.js·unique-mark.png는 scripts/thumb에 있음. 결과는 spec과 같은 폴더에 생김. Chrome·Python PIL 필요)
6. `초안/칼럼_<글번호>.json`: `no`, `blog_title`, `title`, `body_file`, `thumbnail_file`, `title_en`, `body_file_en`, `thumbnail_file_en`, (새 글이면) `faq` — 경로는 JSON 기준 상대경로
7. `node scripts/auto.js preview 초안/칼럼_<글번호>.json` → `초안/칼럼_<글번호>.html`, `_en.html` 검토용. **사용자가 확인한 뒤**
   `node scripts/auto.js column <칼럼id> 초안/칼럼_<글번호>.json`로 DB 저장 (칸: supabase/column_article.sql, column_article_en.sql).
   새 글은 승인 대기, **이미 공개된 글은 저장 즉시 공개 페이지에 반영**.
8. 블로그 성격이 아닌 글(예: 드라마 후기)은 쓰지 말고 사용자에게 칼럼에서 뺄지 묻는다.

## 2. 뉴스레터 초안 → `초안/뉴스레터_YYYY-MM.html`
1. tasks에 나온 이번 달 블로그 글(최대 3개)을 `auto.js blog`로 읽는다.
2. `node scripts/auto.js template`로 최근 발송 회차를 `초안/_지난회차_틀.html`에 받고 **같은 구조·스타일**로 새 회차를 쓴다.
   - 제목(파일 `<title>`과 첫 기사): `[유니크 특허 인사이트 · N월] 대표 기사 제목` ((광고)는 발송 코드가 붙임)
   - 이미지: https://www.unicpat.com/newsletter/... 절대주소만. 새 이미지가 필요하면 public/newsletter/YYYY-MM/에 두고 배포가 필요하다고 알린다
   - '상담 문의' 버튼: https://www.unicpat.com/contact
   - 맨 아래 수신거부 링크 `{{unsubscribe_url}}` 필수 (틀에서 빠져 있으면 추가)
   - 기사 링크: 홈페이지 칼럼(/column/글번호), 공개 전이면 블로그 주소
3. 사용자 안내: 파일을 브라우저로 열어 확인 → 관리자 → 뉴스레터 발송 탭 → 회차 만들기에서 파일 선택 → 미리보기·테스트 발송 → [발송 시작](매일 10시 97명씩 자동).

## 3. 게시글 초안 → `초안/게시글_<글번호>.txt`
구글 비즈니스 프로필·네이버 플레이스 '소식'용. 파일 형식:
```
[제목] (관리용)
[첨부 사진] design/naver-place/place_0N.png
[버튼] 자세히 알아보기 → https://www.unicpat.com/column/<글번호>

(본문 300~600자)
```
- 첫 줄에 고객의 질문/고민. 전화번호·URL은 본문에 넣지 않는다(구글 거부 위험) → 링크는 버튼으로
- 과장·보장 표현 금지. 운영시간: 평일 09:00~18:00, 예약 시 야간·주말 상담
- 사진: design/naver-place/ 중 알맞은 것(place_09 비용표, place_08 오시는 길 등)
- 사용자가 두 곳에 게시하고 자동화 탭 할 일에서 [처리 완료]를 누른다.

## 4. 그 밖의 할 일
- `네이버 수집 요청`: 새 한국어 칼럼마다 생김. 사람이 네이버 서치어드바이저 → 요청 → [웹 페이지 수집]에 주소를 넣음. 네이버 사이트는 Chrome 확장에서 차단되므로 대신 할 수 없다 — 주소 목록만 정리해 안내.
- `구글 색인 요청`: 사람이 서치 콘솔에서 [색인 생성 요청]. Chrome 확장이 있으면 대신 할 수 있다(sc-domain:unicpat.com, 상단 검색창에 주소 → 색인 생성 요청).
- `검색엔진 점검 문제`: 내용을 보고 코드를 고친다(meta description, canonical, SITEMAP_PAGES 누락 등). 커밋·푸시는 사용자 요청이 있을 때만.
- `정부지원사업 후보`: 사용자가 자동화 탭에서 추가/제외. 소개 글을 요청받으면 공고 원문을 읽고 블로그용 초안을 `초안/`에 쓴다.

## 끝나면
만든 파일 경로와, 사용자가 어디서 무엇을 확인·승인할지 짧게 알린다.

## 진행 현황 (2026-11-24)
- 공개 칼럼 62개는 긴 글·영문·썸네일 완료(지식재산 전략 27, 특허 16, 상표·디자인 19). 새 블로그 글만 1번 절차로 쓴다.
- **요약 방식 유지(사용자 결정)** 시기성·공지 글 10개: 2026 정부과제, KEIT, ipbot1, 7월22일 5배 배상, 엔비디아, 피지컬AI, 롯데카드, 스테이블코인, 인천지식재산센터 지원사업 2건. 앞으로 생기는 시기성·공지 글도 사용자에게 물어 정한다.
- `초안/원문확인필요.html/.pdf`는 공개 저장소에 올리지 않는다(내부 확인 문서). 다른 컴퓨터에서는 사용자가 직접 복사한 파일에 이어서 쓴다. 없으면 새로 만들지 말고 사용자에게 묻는다.
- 다른 컴퓨터에서는 `.env`(Supabase 키)가 있어야 auto.js가 동작한다.
